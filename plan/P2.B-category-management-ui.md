`App.tsx` wiring (load categories, pass handlers, store calls) is done by the main agent.

## Contract
```ts
import type { Category, CategoryInput } from '../lib/category'

interface CategoryManagerProps {
  categories: Category[]
  onAdd: (input: CategoryInput) => void
  onRename: (id: string, name: string) => void
  onDelete: (id: string) => void
}
export function CategoryManager(props: CategoryManagerProps): JSX.Element
```
- Lists each category — show its color (a swatch) + name.
- **Add:** a small form (name text input + color input `type="color"`); on submit with a
  non-blank name → `onAdd({ name, color })`, then clear the name field. Blank name →
  inline `role="alert"` message, do not call `onAdd`.
- **Rename:** each row has a control to rename (e.g. an editable text input or an Edit
  button → input). On commit with a non-blank new name → `onRename(id, newName)`.
- **Delete:** each row has a delete button → `onDelete(id)`. `aria-label` includes the
  category name.
- Pure controlled component — NO store/db import. It only emits via the callbacks.
- The component does not validate color or do business rules — that's `createCategory`'s
  job at the App seam. It only guards a blank name for UX.

## Tests (RTL + user-event)
- renders all categories passed in (name visible)
- add: type a name + submit → `onAdd` called once with `{ name, color }`; name field clears
- add: blank name + submit → `onAdd` NOT called, alert shown
- rename: change a row's name + commit → `onRename` called with that id + the new name
- delete: click a row's delete button → `onDelete` called with that id
