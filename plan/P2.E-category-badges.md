# P2.E — Category badges

Add a colored category badge per expense row in `ExpenseList`.

## Files (allowlist)
- `src/components/ExpenseList.tsx` (modify)
- `src/components/ExpenseList.test.tsx` (modify)
- `src/components/ExpenseList.css` (modify)

`src/App.tsx` is NOT in the allowlist — the main agent passes `categories`.

## Contract
`ExpenseListProps` gains a required `categories` prop:
```ts
import type { Category } from '../lib/category'
interface ExpenseListProps {
  expenses: Expense[]
  categories: Category[]          // NEW (required)
  onDelete?: (id: string) => void
  onEdit?: (expense: Expense) => void
}
```
For each row:
- If `expense.categoryId` is set AND a matching `Category` exists in `categories`:
  render a small badge — a colored swatch (background = category color) + the
  category name. The badge has `aria-label={`Category: ${category.name}`}`.
- Otherwise (no `categoryId`, OR `categoryId` doesn't match any category — orphan
  from a deleted category, see TD.6): render NO badge. Don't render "Uncategorized";
  silence is fine here.

Place the badge as a new grid column in the row. Update `expense-list.css`
`grid-template-columns` to accommodate it. Keep semicolons (existing file style).

## Tests (update ExpenseList.test.tsx — keep ALL existing tests passing)
Adding required `categories` breaks every existing render call. Use a shared
`categories` const / `setup` helper so all 11 existing tests still construct a
valid element. Then add:
- a row with `categoryId` matching a category renders a badge with that name + color
  applied (assert via `style.backgroundColor` on the swatch element)
- a row WITHOUT `categoryId` renders no badge
- a row with `categoryId` not in the `categories` prop (orphan) renders no badge

## Peer-review charter
Verify `categories` prop wired correctly; the orphan/missing case renders no badge
(no crash, no leak); existing 11 tests still pass; badge color comes from category.color
(not hard-coded); ordering/no-mutation behaviour of the list unchanged.
